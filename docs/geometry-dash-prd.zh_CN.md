## 1. 产品目标与范围

### 1.1 一句话体验

把设备横过来握在手里，一个方块随着音乐自动向右冲刺；玩家只用"跳"这一个动作，配合节拍越过尖刺、
踩跳板、点跳环、驾驶飞船、翻转重力。死了立刻重来，直到把一关打到 100%。

### 1.2 目标

- **G1 手感优先**：跳跃时机与音乐节拍对齐，按下即响应，失败后 1 秒内重来。
- **G2 音乐陪伴**：每关一首原创配乐，画面推进与音乐严格同步，掉帧不影响判定。
- **G3 可持续挑战**：6 个难度递进的关卡，逐关引入新机制；提供练习模式和进度记录。
- **G4 稳定可验收**：核心玩法是纯 C、可在主机上测试；每关都能由机器人求解器证明可以通关；
  性能、内存和音频指标在真机上可测。

### 1.3 非目标

以下内容不在本版本范围内：在线关卡与账号、设备端关卡编辑器、球 / UFO / 波浪 / 机器人 / 蜘蛛形态、
变速门、镜像门、双人模式、金币与图标解锁、Wi-Fi / BLE 功能、深度睡眠。

## 3. 硬件与 BSP 前置条件

### 3.1 屏幕方向

固定横屏 320×240，**侧键朝上**：设备逆时针旋转 90°，挂绳孔在左。顶边从左到右依次是实体键
**上（UP）/ 下（DOWN）/ 确定（OK）**，以下简称**左键 / 中键 / 右键**。

### 3.2 需要移植的 BSP 改动（P0，实现阶段的第一步）

| 来源 | 内容 | 状态 |
| --- | --- | --- |
| Rhythm 项目提交 `472027c`（`feat(bsp): add landscape orientation and side-key positions`） | `bsp_lvgl_set_orientation()`；圆角遮罩改用逻辑分辨率；`BSP_LCD_ROTATION_KEYS_TOP/BOTTOM`；`BSP_BTN_EDGE_POS_TABLE {43,164,280}` | KEYS_TOP 方向已于 2026-10-06 实机确认；按键位置表按渲染图换算（±10 px），尚未实机确认 |
| metronome 项目提交 `332bb67`（`feat(bsp): add button release event and expose I2S DMA size`） | 新增 `BSP_BTN_RELEASE`（映射 iot_button `BUTTON_PRESS_UP`），供"按住连跳"和飞船使用 | 该项目已整体实测，但这一事件未逐项记录 |
| Rhythm 项目提交 `47c39b6` | `tools/validate.sh` 在 macOS 上把 `--gc-sections` 换成 `-dead_strip` | 不移植的话，macOS 上的 `--static` 会在链接 demo 运行时测试时失败 |

两个 BSP 提交都新增了 `BSP_AUDIO_DMA_DESC_NUM` / `BSP_AUDIO_DMA_FRAME_NUM`，移植时手工合并为一份。
同步更新 BSP 主机测试和中英文硬件指南。不得复制 demo 里的引脚或电压常量。

### 3.3 硬件约束（实现必须遵守）

- 按键：三键共用 GPIO0 上的 ADC 电阻分压（`BSP_BTN_MV_TABLE`），**同一时刻只能识别一个键**，
  不设计任何组合键。按键组件轮询周期约 5 ms；`BSP_BTN_PRESS` 在按下沿触发，延迟最低。
- 按键回调运行在共享的 `esp_timer` 任务中：只能记录 `esp_timer_get_time()` 时间戳并入队，
  不能阻塞，也不能访问 LVGL。
- 显示：SPI 80 MHz、单个 40 行 DMA 绘制缓冲。一整帧 320×240 RGB565 是 153.6 KB，仅 SPI 传输
  就要约 15 ms，渲染与传输串行。BSP 不提供 TE 引脚，无法做到严格防撕裂。
- 四角有 30 px 圆角遮罩（`BSP_LVGL_SCREEN_RADIUS`），重要内容不得放在四角。
- 音频：I2S DMA 队列 6×240 帧，16 kHz 时约 90 ms。`bsp_audio_write()` 是阻塞调用，
  只能由一个音频任务调用。
- 内存：没有 PSRAM，不得分配整帧缓冲；不初始化 Wi-Fi 和 BLE。
- 固件只编译应用自己的源文件（参考 Rhythm：只编 `main.c` 和应用文件），开机直接进入几何冲刺，
  不再出现基线测试菜单。

## 4. 操作映射（P0）

所有页面都在顶边对准实体键显示按键标签（x 取自 `BSP_BTN_EDGE_POS_TABLE`，横屏侧键朝上时
x ≈ 表中数值），标签内容随页面变化。**游戏进行中隐藏标签**，以免遮挡视野。

| 场景 | 左键（上） | 中键（下） | 右键（确定） |
| --- | --- | --- | --- |
| 标题页 | 设置 | 统计 | 开始（进入选关） |
| 选关页 | 上一关 | 下一关 | 单击开始；长按返回标题 |
| 游戏中（普通模式） | 跳跃/飞行，按住连跳 | 暂停 | 跳跃/飞行，按住连跳 |
| 游戏中（练习模式） | 跳跃/飞行 | 单击放置检查点；长按暂停 | 跳跃/飞行 |
| 暂停菜单 | 上移 | 下移 | 执行；长按等同"继续" |
| 通关结算 | 再玩一次 | — | 返回选关 |
| 设置 / 统计 | 上移（调值时减少） | 下移（调值时增加） | 进入/确认；长按返回 |

输入规则：

- **跳跃输入使用 PRESS（按下沿）和 RELEASE（松开沿）**，不依赖 CLICK，避免 180 ms 的单击判定延迟。
  "按住"状态 = 最近一次跳跃键 PRESS 之后还没有收到 RELEASE。
- 按键时间戳在回调中记录。物理模拟在该时间戳对应的物理步施加输入，而不是在"任务处理到它"的那一刻施加，
  所以任务调度抖动不影响判定。
- 菜单中一次物理按下只触发一次动作：PRESS 与随后到来的 CLICK 不得重复执行（参考 Tetris demo 的做法）。
- 长按阈值沿用 `BSP_BTN_LONG_PRESS_MS`（500 ms）。

## 5. 页面与流程（P0，全部重新设计）

全部页面都是本应用新设计的，不得使用 `main` 的测试菜单、`demo_*.c` 页面或 `ui_pixel` 外壳。

### 5.1 视觉风格

- 霓虹几何风：纯色或竖直渐变背景，黑色实心方块配亮色描边，尖刺为黑底亮边三角，地面为带亮线的色带。
- 每关一个主题色：背景色、地面色和描边色由主题统一给出（见 §6）。
- 玩家图标为原创方块角色：主色黄 `#FFD400`、副色青 `#00E5FF`，带简单"脸"图案。飞船为原创三角船体，方块坐在舱内。
- 文字使用中文字体子集（见 §11）。英文关卡名使用同一字体中的拉丁字形。

### 5.2 页面清单

| 页面 | 内容 | 优先级 |
| --- | --- | --- |
| 标题 | 大字标题"几何冲刺"，方块角色在地面上来回跳跃的待机动画，背景方块缓慢漂移；右上角显示电量；顶边三个按键标签 | P0 |
| 选关 | 横向卡片轮播：关卡序号、英文曲名、作者、难度标识（简单 / 普通 / 困难）、普通模式进度条与百分比、练习模式进度条与百分比、已通关标记。卡片背景取该关主题色，切换时平滑滑动 | P0 |
| 游戏 | 全屏卷轴场景；顶部中央细进度条和百分比（可在设置中隐藏）；每局开头在世界坐标中显示"第 N 次尝试"，随场景一起卷走；练习模式下显示检查点菱形标记 | P0 |
| 暂停 | 半透明遮罩覆盖冻结的画面，菜单为：继续 / 练习模式：开/关 / 重新开始 / 返回选关；显示当前关卡名、本次进度与电量 | P0 |
| 死亡反馈 | 方块碎成 8–12 块飞散，加一个闪光环，持续 0.6 s 后自动重开，尝试次数加 1；死亡时音乐停止 | P0 |
| 通关 | 玩家进入终点后画面定格，飘出"关卡完成！"；1.5 s 后进入结算页，显示尝试次数、跳跃次数、用时，以及"新纪录"标记 | P0 |
| 设置 | 音乐音量（0–10 档，默认 6）；音效开/关；进度条显示/隐藏；屏幕亮度（3 档）；音画偏移（−100 ~ +100 ms，步进 10 ms）；清除存档（长按右键 1.5 s 确认）；关于与版权声明 | P0（音画偏移为 P1） |
| 统计 | 总尝试次数、总跳跃次数、已通关关卡数、累计游戏时长 | P1 |
| 静音模式提示 | 没有有效音乐包时，选关卡片显示"未内置音乐（静音游玩）"，游戏以 `esp_timer` 为时钟继续可玩 | P0 |
| 首次引导 | 第 1 关第 1 次尝试的开头浮现"左/右键：跳跃 · 中键：暂停"，3 s 后淡出 | P1 |

### 5.3 主流程

```text
上电 → 标题 ──右键──→ 选关 ──右键──→ 游戏 ──中键──→ 暂停 ──→ 继续 / 重开 / 返回选关
          │                 ↑                │
          ├─左键→ 设置       │                ├─撞到障碍→ 死亡 0.6 s → 自动重开（尝试 +1）
          └─中键→ 统计       └──右键── 结算 ←─┴─到达终点→ 通关
```

- 电量显示在标题、选关和暂停页的右上角，位于按键标签下方，不与标签重叠。
  `bsp_battery_soc()` 返回 −1 时不显示数字，也不编造百分比。
- 菜单页空闲 2 分钟后背光降到 20%，任意键恢复；这次按键只用于唤醒，不触发功能（P1）。

## 6. 关卡（P0）

### 6.1 关卡与曲目

关卡长度按每关 85–95 s 设计。音乐从曲首截取到关卡结束，再加 3 s 淡出；音乐包中每首最长 95 s。

| # | 关卡(曲名) | BPM | 首拍 | 难度 | 新机制 | 主题色 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | Neon Takeoff | 160 | 351 ms | 简单 | 方块跳跃、方块平台、一段飞船 | 蓝 |
| 2 | Pad Runner | 142 | 346 ms | 简单 | 黄色跳板 | 紫 |
| 3 | Orb Drift | 155 | 63 ms | 普通 | 黄色跳环 | 绿 |
| 4 | Upside Dune | 145 | 245 ms | 普通 | 重力门、蓝色跳环 | 橙 |
| 5 | Base Breaker | 141 | 428 ms | 困难 | 飞船段中翻转重力、蓝色跳板 | 青 |
| 6 | Final Pulse | 170 | 216 ms | 困难 | 综合:高密度跳环连跳、重力切换 | 洋红 |

BPM 与首拍最初是从初稿原曲估算的,关卡按它们编排;原创配乐直接按同样的 BPM 与首拍作曲,拍点与障碍保持对齐。

### 6.2 关卡设计规则

- 开头留 3 s 以上平地助跑。每关分成 6–10 个段落，段落之间给 1–2 拍的喘息区。
- 新机制首次出现时必须"安全示范"：第一次遇到跳板或跳环时，失败的代价很低。
- 障碍放在网格上（1 格 = 20 px）。节拍落点会被量化，最大误差为半格（约 48 ms）；
  重拍上的障碍应选择最接近拍点的格子。
- 难度递进：简单关不出现三连刺和需要连点的跳环；困难关允许三连刺、连续跳环和飞船窄道（最窄 3 格）。
- 每关都必须通过 §12 的机器人可通关证明，并报告"最小容错窗口"。简单关的最小窗口 ≥ 50 ms，
  普通关 ≥ 33 ms，困难关 ≥ 20 ms。
- 终点：最后 2 s 为无障碍跑道，之后进入终点门。

## 7. 游戏规则与物理（P0）

### 7.1 坐标与视野

- 1 格 = 20 px。可见区域 16 格宽 × 12 格高:顶部 1 格是天花板带(内含进度条),底部 2 格是地面带,
  中间 9 格(180 px)是可玩区。
- 玩家固定在屏幕 x = 4 格处，所以前方可见 12 格，正常速度下约 1.15 s 的预判时间。
- 镜头只水平卷动、竖直方向固定(竖直移动会让整屏重画,破坏 §9.1 的脏矩形方案)。地面与天花板在两种形态下
  都是实心表面:方块正常重力时顶到天花板只是停止上升,倒立重力时站在天花板上;飞船的通道就是这 9 格。

### 7.2 物理参数（初始值，集中在一个头文件中，实测后调参）

| 参数 | 初始值 | 说明 |
| --- | --- | --- |
| 水平速度 | 208 px/s（约 10.4 格/s） | 全程恒定，本版本没有变速门 |
| 物理步长 | 240 Hz 固定步长 | 整数定点（建议 Q8 子像素），主机、Wasm 与设备逐位一致 |
| 方块起跳速度 | 400 px/s | 跳高 = 42 px（约 2.1 格） |
| 方块重力 | 1905 px/s² | 平地滞空约 0.42 s，水平距离约 87 px（约 4.4 格） |
| 黄色跳板 | 起跳速度 × 1.35 | 跳高约 3.8 格 |
| 黄色跳环 | 空中重新获得一次标准起跳速度 | — |
| 蓝色跳环 / 蓝色跳板 | 翻转重力，竖直速度设为朝新方向的 0.4 × 起跳速度 | — |
| 飞船上升加速度 | 1100 px/s²（按住时） | — |
| 飞船下降加速度 | 1000 px/s²（松开时） | — |
| 飞船最大竖直速度 | ±260 px/s | 船头角度跟随速度方向，仅作视觉 |
| 最大下落速度（方块） | 650 px/s | — |

**必须用主机测试固化的不变量**：

1. 平地上的方块能跳过连续 3 个地刺，跳不过连续 4 个。
2. 方块能跳上高 1 格和 2 格的方块平台，跳不上 3 格。
3. 不同调用帧率下，同一输入序列得到相同的轨迹（固定步长确定性）。

### 7.3 碰撞

- 玩家外框 20×20 px，用于着陆和拾取门、跳板、跳环。
- 玩家内核 6×6 px（居中）：内核碰到实心方块即死亡，也就是侧面撞墙或头顶撞到方块底。
- 着陆：下落时，如果外框底边进入方块顶面以下不超过 7 px 且内核没有碰到方块，就吸附到顶面。
  反重力时同理，以方块底面为"地面"。
- 尖刺判定框是缩小的：宽 4 px、高 8 px，位于尖刺下部中央，比画面上的三角形宽容。外框碰到即死亡。
- 跳环判定为半径 12 px 的圆，跳板判定为宽 16 px、高 4 px 的贴地矩形，传送门判定为宽 10 px、高 60 px（3 格）的矩形。
- 地面与天花板之外的区域为致死区（防止穿出通道）。

### 7.4 机制细则

| 机制 | 规则 |
| --- | --- |
| 跳跃 | 只在着地时生效。按住时每次着地立即再次起跳（按住连跳） |
| 跳环 | 外框与跳环重叠期间出现 PRESS 即触发。如果 PRESS 发生在进入重叠前 ≤ 50 ms 内并且一直按住，进入时触发（输入缓冲）。每个跳环每局只能触发一次 |
| 跳板 | 接触即触发，无需按键 |
| 重力门 | 蓝门 = 翻转为倒立重力，黄门 = 恢复正常重力。只有重力方向改变时才生效 |
| 形态门 | 粉门 = 切换为飞船，绿门 = 切换为方块。切换保留竖直速度的 50% |
| 飞船 | 按住上升，松开下降；碰到天花板、地面、方块顶面或方块底面都不会死亡，会贴着滑行；撞到方块侧面或尖刺会死亡 |
| 终点 | 玩家 x 越过终点线即判定通关，之后忽略一切碰撞 |

### 7.5 时钟与同步

- **音频是主时钟**（沿用 Rhythm `rh_audio` 的做法）：当前歌曲时间 = 已写入 I2S 的采样数 − DMA 队列容量，
  两次写入之间用 `esp_timer` 插值，外推上限 20 ms。每次开始或继续播放前先写满一个队列的静音。
- 每一帧开始时，物理从上一步追到"歌曲时间 + 音画偏移 − 6 ms 输入宽限"对应的步数(宽限让按键事件先到达)。
  单帧最多追 40 步（约 167 ms）；落后更多时分几帧追上，不瞬移，音乐也不倒退、不加速。
- 掉帧只会让画面变卡，不会改变判定和轨迹。
- 没有音乐包或音频初始化失败时，改用 `esp_timer` 虚拟时钟，游戏照常可玩。

### 7.6 进度、尝试与练习模式

- 进度百分比 = ⌊玩家 x / 终点 x × 100⌋，范围 0–100。普通模式死亡时，如果超过最佳进度就刷新并提示"新纪录 xx%"。
- 普通模式：死亡后从关卡开头重来，音乐从 0 开始，尝试次数 +1。
- 练习模式（P0）：
  - 自动检查点：玩家稳定着地 ≥ 0.1 s，且距上一个检查点 ≥ 2 s 时自动放置。
  - 手动检查点：中键单击放置，前提是当前位置安全（着地或飞船在通道内）（P1）。
  - 检查点保存完整的玩家状态（位置、速度、重力、形态、按住状态），最多保留 32 个，超出后丢弃最早的。
  - 死亡后回到最近的检查点，音乐跳转到该检查点对应的歌曲时间继续播放；检查点之后的跳环恢复可用。
  - 练习最佳进度单独记录。练习模式下通关只标记"练习通关"，不计为正式通关。
- 在暂停菜单切换练习模式时，从当前关卡开头重新开始。

## 8. 音频（P0）

### 8.1 格式与预算

- 格式：**IMA-ADPCM 4-bit、16 kHz、单声道**。解码器几乎不占 Flash 和 CPU，块结构天然支持练习模式的跳转。
  MP3 或 Opus 会在单核 C3 上与渲染抢 CPU，并多占 30–80 KB Flash，本版本不采用。
- 实测(2026-10-07):每首 95 s(末尾 3 s 淡出),单首 762,880 B(约 8.0 KB/s),6 首合计约 4.58 MB。

### 8.2 分区布局

| 分区 | 类型/子类型 | 偏移 | 大小 | 说明 |
| --- | --- | ---: | ---: | --- |
| `nvs` | data/nvs | `0x9000` | `0x6000` | 不变 |
| `phy_init` | data/phy | `0xF000` | `0x1000` | 不变 |
| `factory` | app/factory | `0x10000` | `0x200000`（2 MB） | 基线应用实测 1,524,336 B（含 BT/Wi-Fi）；本应用预计 ≤ 1.2 MB |
| `music` | data/0x40（自定义） | `0x210000` | `0x5F0000`（约 5.94 MB） | 音乐包；6 首约占 77%，剩余约 1.6 MB 可再放 2 首（P2） |

布局结束于 `0x800000`，正好 8 MB。修改 `partitions.csv` 后，`verify_firmware.py` 和
[固件布局](development/engineering/firmware-layout.zh_CN.md) 的强制验证必须通过，并在项目文档中写明烧录说明。

### 8.3 音乐包生成与构建

- 工具 `tools/gen_gd_music.py`(P0,需要 numpy):调用 `tools/gd_music_synth.py` 按 `assets/levels/tracks.json`
  (曲名、BPM、首拍、调式、和弦进行、音色、随机种子、长度与淡出)作曲合成,编码为 IMA-ADPCM(重建公式与固件解码器
  一致),生成 `build/gd_music/gd_music.bin` 和 manifest;`--wav-dir` 可另存 WAV 试听。
- 音乐包格式（小端）：头部为 magic `GDMU`、版本、曲目数、头部 CRC32；
  索引表每项包括关卡号、采样率、块对齐、每块采样数、数据偏移、字节数、总采样数、数据 CRC32；
  之后是 IMA-ADPCM 数据块。
- CMake 用 `esptool_py_flash_to_partition` 把存在的音乐包注册到 `music` 分区，
  这样 `./tools/validate.sh` 的 `merge-bin` 会自动把它并入 `FoloToy-AI-Passport-full.bin`。
  音乐包不存在时只打印警告，构建照常成功(CI 等没有生成音乐包的环境也能构建,固件静音运行)。
- 开发时可以只刷应用分区，不必每次重刷约 4.6 MB 的音乐。

### 8.4 运行时

- 启动时读取并校验音乐包头部和索引的 CRC。无效时进入静音模式（§5.2）。
  第一次播放某首曲目时在后台校验其数据 CRC，失败则该关静音并在日志中记录（P1）。
- 音频任务是唯一调用 `bsp_audio_*` 的任务，优先级高于 LVGL 任务（参考 Rhythm：音频 6、LVGL 4）。
  它用 `esp_partition_read()` 每次读取 ≥ 1 KB，或者分段映射，**不得一次映射整个分区**；
  解码后以 240 帧为单位写出。
- 音量：`bsp_audio_set_volume()` 结合软件增益，10 档。音效开关只影响音效（P1：死亡碎裂声、通关音效、
  菜单提示音，用小型合成器与音乐混音）。
- 开启 `CONFIG_I2S_ISR_IRAM_SAFE=y`。**只在音乐不推进时写 NVS**(停止或暂停):死亡动画期间、通关后、暂停时、
  退出关卡时。音效只用内存里的合成数据,可以与写 Flash 同时进行。

## 9. 渲染与性能（P0）

### 9.1 渲染方案要求

- 背景只允许"纯色或竖直渐变"（同一行颜色相同）。这样水平卷动时，只需重绘移动物体新旧位置的包围盒（脏矩形），
  不需要整屏重绘。远景装饰（P2）只能低频更新。
- 推荐方案：参考 Rhythm，用一个全屏 `lv_obj` 加 `LV_EVENT_DRAW_MAIN` 回调，以立即模式绘制。
  每帧把上一帧和这一帧的物体包围盒并集作废，脏矩形数量超过上限时整屏重绘。
  一帧只取一次时间，让所有 40 行分块看到同一状态。
- **M0 性能探针**：选取关卡中最密集的一段，用机器人自动游玩，在设备上实测上述方案的帧率。
  不达标时，改为通过 `bsp_display_panel()` + `esp_lcd_panel_draw_bitmap()` 用行缓冲直接推送脏矩形
  （大端 RGB565，详见[显示刷新经验](reference/shinku-chen/display-refresh-and-deep-sleep.zh_CN.md)）。
  方案以实测结果为准。
- 不使用整帧缓冲。可见物体从关卡的 x 排序数组中二分查找可见窗口，每帧遍历量与关卡长度无关。

### 9.2 可测目标

| 指标 | 目标 | 测量方法 |
| --- | --- | --- |
| 游戏中帧率 | 每个 10 s 窗口平均 ≥ 30 fps（期望 40–50 fps）；帧间隔 > 66 ms 的次数每分钟 ≤ 3 次 | 串口每秒输出一行 `fps / max_frame_ms / render_ms` |
| 输入到画面 | 按下到画面上出现起跳 ≤ 50 ms | 240 fps 手机慢动作视频（P1，未测时列入未验证项） |
| 输入到判定 | 0 ms 游戏时间偏差（按时间戳施加） | 主机测试 + 日志对比按键时间戳与起跳物理步 |
| 音频连续性 | 整关游玩中欠载次数 = 0 | 音频任务统计"两次写入间隔 > 队列时长"的次数 |
| 内存 | 游戏中最小空闲堆 ≥ 40 KB、最大连续块 ≥ 16 KB；LVGL 池峰值 ≤ 80% | 每 5 s 输出 `heap_caps_get_free_size` / `largest_free_block` |
| 启动 | 上电到标题页可操作 ≤ 2 s | 串口时间戳 |
| 稳定性 | 连续游玩 30 分钟无重启、看门狗或分配失败，空闲堆无持续下降 | 长时间测试日志 |

## 10. 存档（P0）

- 使用 NVS 命名空间 `gdash` 下的一个 blob，带 schema 版本号。读取时检查版本和长度，非法字段钳位到合法范围。
- 存储内容：每关的普通最佳进度、练习最佳进度、是否正式通关、是否练习通关、尝试次数、跳跃次数，
  外加总游戏时长和设置项（音量、音效、进度条、亮度、音画偏移）。
- 写入时机：
  - 刷新最佳进度时，在死亡动画期间写入。
  - 尝试次数和跳跃次数在通关、暂停、退出关卡时写入；意外掉电最多丢失当前关卡尚未写入的计数。
  - 设置在退出设置页时写入。
- "清除存档"需要长按确认。清除后回到默认值，保留设置。
- 通过 `0x0` 刷写合并镜像会重置存档；README 和交付说明中必须写明这一点。

## 11. 中文字体（P0）

- 所有界面文字集中在 `main/gd_strings.h`。工具检查：在该文件之外出现非 ASCII 字符串字面量时报错（参考 Rhythm）。
- 生成脚本 `tools/gen_gd_fonts.py` 调用 `npx lv_font_conv@1.5.3`，参数为 `--bpp 4 --no-compress`，
  字体文件是 Source Han Sans SC（本机 `~/esp/fonts/source-han-sans-2.005/`）。生成以下子集：
  - Bold 14 / 16 / 20 px：全部界面文字 + ASCII
  - Heavy 36 px：标题"几何冲刺"、"关卡完成！"和数字 + `%`
  - 输出写入 `assets/fonts/`，并记录 manifest 和 SHA-256
- 每个控件的每个部件和状态都要显式设置字体；`LV_SYMBOL_*` 通过 fallback 到 Montserrat 显示。
- 验收：
  - 主机测试检查每个码点都满足 `lv_font_get_glyph_dsc()` 返回非占位字形，并包含 U+9F98 这个负例。
  - 开机自检所有文字的字形覆盖。
  - 真机目视确认没有方框或空白。

## 12. 关卡数据与工具链

- 关卡源文件（P0）：`assets/levels/level_<n>.txt`，原创且提交进仓库。文件头写明 BPM、首拍、主题、长度；
  正文是 ASCII 网格，每个字符 1 格，最底行是地面层：

  | 字符 | 含义 | 字符 | 含义 |
  | --- | --- | --- | --- |
  | `.` | 空 | `#` | 实心方块 |
  | `^` | 地刺（朝上） | `v` | 顶刺（朝下） |
  | `y` | 黄色跳板 | `o` | 黄色跳环 |
  | `B` | 蓝色跳板 | `b` | 蓝色跳环 |
  | `G` | 重力门（翻转） | `g` | 重力门（恢复） |
  | `S` | 飞船门 | `C` | 方块门 |
  | `E` | 终点 | `=` | 飞船段的天花板/地面边界 |

- `tools/gen_gd_levels.py`（P0）：
  - 把关卡编译为按 x 排序的紧凑对象数组 `main/gd_levels_data.c`，生成物提交进仓库，并记录源文件哈希；
    过期时让检查失败。
  - `ruler` 子命令按 BPM 和首拍在网格上方打印节拍标尺，供设计时对拍。
  - `render` 子命令把整关渲染成 PNG 长图，供评审。
- 机器人求解器（P0）：在主机上用同一份物理代码搜索输入序列，证明每关都能通关。
  它输出一条可回放的输入录像，并报告每处的最小容错窗口（§6.2）。录像回放作为回归测试。
- 自动游玩调试模式（P1）：在编译开关下，设备回放录像自动通关，用于在固定场景下重复测量 §9.2 的性能。
- 主机预览(实现时以此代替 H5/Wasm 试玩页):`tools/render_gd_preview.py` 在电脑上用真实 LVGL 编译固件界面与
  对局代码,按固件相同的分块局部刷新渲染各页面,用录像把 6 关各自动玩一遍,检查局部刷新与整屏重画逐像素一致,
  并统计 LVGL 内存池峰值与每帧推送像素量。H5/Wasm 试玩页未做(P2)。

## 15. 风险与待定项

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 卷轴渲染帧率不足 | 画面卡顿、难以预判 | 背景限定为竖直渐变；M0 探针；必要时改为直接推送面板；降低粒子数量 |
| 没有 TE 引脚导致撕裂 | 快速卷动时出现斜切 | 保持帧率稳定；由用户目视评估，作为已知限制记录 |
| 音频爆音或欠载 | 节奏感被破坏 | 音频任务高优先级；只在音乐停止时写 Flash；开启 IRAM 安全 ISR；统计欠载次数 |
| ADC 按键松开检测有延迟 | 飞船操控偏"粘" | 实测 RELEASE 延迟；必要时调整飞船参数来补偿 |
| BPM 估算偏差 | 障碍与重拍错位 | 用节拍标尺人工校准；设置中提供音画偏移 |
| 关卡设计工作量大 | 进度延后 | 先做第 1 关打通全链路；求解器自动检查可通关性；用 PNG 长图评审 |
| 版权 | 误把原曲打进固件 | 配乐改为原创合成;`gen_gd_music.py` 不再读取 `BGM/`;"关于"页声明非官方致敬 |
| 按键位置表未经实机确认 | 按键标签可能偏离实体键 ±10 px | M0 实机核对；必要时修正 `BSP_BTN_EDGE_POS_TABLE` |
